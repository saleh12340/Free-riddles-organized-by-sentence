# تطوير الفواتير وكشوفات الحسابات والتحديد المتعدد

خطة تنفيذ هندسية شاملة لتلبية متطلبات النظام المحاسبي: استبدال الخصم بالمبلغ الواصل واحتساب المتبقي تلقائياً، تفعيل اقتراحات العملاء ومنع تكرار الأسماء، وتطوير شاشة كشف حساب العميل لتشمل التفاصيل المصغرة للعمليات بترتيب زمني من الأحدث مع الرصيد التراكمي يسار كل حركة، وإضافة إمكانيات الطباعة والمشاركة والتعديل والتحديد المتعدد للعمليات والفواتير والأصناف.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> يرجى مراجعة القرارات التصميمية التالية قبل بدء التنفيذ:
> - **المبلغ الواصل والمتبقي في الفاتورة**: عند إدخال المبلغ الواصل في أسفل الفاتورة، يُحسب المتبقي تلقائياً (`المتبقي = الإجمالي العام - الواصل`). إذا كان المتبقي أكبر من صفر، يُرحل تلقائياً إلى رصيد حساب العميل كدين، ويُطبع المبلغ الواصل والمتبقي بوضوح في أسفل الفاتورة الورقية والحرارية وPDF.
> - **منع تكرار اسم العميل**: فحص فوري عند كتابة اسم العميل أو إضافته في قاعدة البيانات لمنع تسجيل نفس الاسم مرتين مع إظهار تنبيه توضيحي واقتراح الأسماء المتطابقة فورياً.
> - **التحديد المتعدد**: تفعيل شريط إجراءات جماعية عائم وسلس (Batch Action Bar) يتيح تحديد عدة عمليات أو فواتير للطباعة، المشاركة كملف واحد، أو الحذف الجماعي بعد التأكيد.

---

## 1. Overview & Core Concept

- **الهدف الرئيسي**: جعل تجربة إنشاء الفواتير وإدارة حسابات العملاء احترافية، سلسة، ومتكاملة محاسبياً وسهلة الاستخدام في بيئة المتاجر اليومية.
- **الفئة المستهدفة**: أصحاب المحلات والمتاجر ومسؤولو المبيعات الذين يحتاجون إلى سرعة في تسجيل المدفوعات النقدية والآجلة، ومتابعة دقيقة لأرصدة العملاء لحظة بلحظة.
- **القيمة المضافة**:
  - استبدال حقل الخصم بمفهوم "المبلغ الواصل" المألوف تجارياً، مع احتساب فوري للمتبقي.
  - إيقاف الأخطاء الشائعة لتكرار العملاء مع دعم إكمال تلقائي مريح.
  - شاشة كشف حساب متطورة تتيح معاينة تفاصيل الفاتورة المصغرة بنقرة واحدة، طباعة حرارية أو PDF، مشاركة عبر واتساب، وتعديل أي حركة فورياً.

## 2. User Experience & Visual Design

### 2.1. أسفل الفاتورة (Interactive Receipt View)
- استبدال حقل الخصم السابق بشريط أنيق:
  - **الإجمالي العام (Grand Total)**.
  - **المبلغ الواصل (Amount Paid)**: حقل إدخال رقمي مباشر، يدعم الأرقام الإنجليزية افتراضياً، مع زر سريع "واصل كامل".
  - **المتبقي (Remaining / Balance)**: شارة بلون بارز (أزرق غامق إذا كان متبقي، أو أخضر إذا كان خالصاً).
- ظهور نفس التنسيق في المعاينة والطباعة الحرارية 80mm/58mm والـ PDF بخط "الأميري".

### 2.2. شريط اسم العميل والاقتراحات الذكية
- حقل اسم العميل في الفاتورة يعرض نافذة منسدلة أو شرائح مقترحة فورية (Suggestions Dropdown / Chips) بمجرد الكتابة، مستمدة من جدول العملاء وسجلات الفواتير السابقة.
- منع حفظ عميل جديد بنفس الاسم مع إبراز تحذير فوري إذا وجد اسم مطابق.

### 2.3. شاشة كشف حساب العميل (Customer Statement)
- **شريط علوي متكامل**: يتضمن أزرار الطباعة الحرارية والمشاركة بتنسيق PDF أو نص واتساب.
- **سجل العمليات المصغر والأحدث أولاً**:
  - كل صف يمثل عملية (فاتورة بيع أو سند قبض).
  - جهة اليمين: نوع الحركة (فاتورة / سند)، رقمها، تاريخها، وعدد أصنافها.
  - نقرة على الصف تفتح تفاصيل مصغرة قابلة للطي (Mini Details Dropdown) تعرض الأصناف، الكميات، والأسعار.
  - جهة اليسار: مبلغ الحركة، والرصيد التراكمي المحدث لحظياً بعد تلك الحركة (`رصيد: XXX ر.ي`).
  - أزرار سريعة لكل صف: تعديل (Edit) ينقل الفاتورة للتحرير أو يفتح حوار تعديل السند، زر طباعة، وزر مشاركة.
- **وضع التحديد المتعدد (Multi-Selection Mode)**:
  - ضغطة مطولة أو تفعيل زر التحديد يظهر مربعات اختيار (Checkboxes) بجانب كل عملية أو فاتورة.
  - شريط إجراءات سفلي / علوي يقدم: "طباعة المحدد"، "مشاركة المحدد كتقرير مجمع"، "حذف المحدد"، مع عداد للعناصر المختارة وزر "تحديد الكل".

## 3. Key Product Decisions & Trade-Offs

1. **إدارة المبلغ الواصل والمتبقي**:
   - *القرار*: تخزين `paidAmount` و `remainingAmount` في `InvoiceEntity` وربط المتبقي ديناميكياً مع جدول كشف الحساب.
   - *السبب*: دقة محاسبية متناهية تضمن أن رصيد العميل لا يتأثر إلا بالمتبقي الفعلي غير المدفوع من الفاتورة.
2. **عرض تفاصيل العمليات المصغرة**:
   - *القرار*: عرض بطاقات مدمجة (Compact Rows) قابلة للتوسعة السريعة (Accordion / Expandable) بدلاً من فتح شاشة جديدة لكل تفصيل.
   - *السبب*: الحفاظ على تدفق العمل السريع للتاجر دون إرباك التنقلات بين الشاشات.
3. **التحديد المتعدد والعمليات المجمعة**:
   - *القرار*: دعم التحديد في شاشة كشف الحساب (للعمليات) وشاشة سجل الفواتير، وتوليد تقرير موحد عند طلب طباعة أو مشاركة العمليات المحددة.
   - *السبب*: تجنب هدر ورق الطابعة الحرارية وتوفير تقرير منظم وشامل للعميل.

### خطة تنفيذ المكونات:
1. **تحديث الـ Entities والـ Database**:
   - إضافة حقلي `paidAmount` و `remainingAmount` في `InvoiceEntity`، وتحديث دوال الـ DAO.
2. **تحديث `InvoiceViewModel`**:
   - إدارة حالة المبلغ الواصل والمتبقي، واقتراحات العملاء الحية، ومنع حفظ العميل المكرر.
   - إضافة دوال التعديل والحذف الجماعي والطباعة المجمعة.
3. **تحديث `InteractiveReceiptView` و `ReceiptBitmapHelper`**:
   - استبدال الخصم بالواصل والمتبقي، وتحديث نموذج الطباعة الحرارية بالخط الأميري ليتضمن الواصل والمتبقي.
4. **تطوير `CustomerAccountStatementScreen`**:
   - إعادة بناء القائمة لتعرض العمليات الأحدث أولاً مع تفاصيل الأصناف المدمجة والرصيد التراكمي على اليسار.
   - إضافة خيارات: تعديل، طباعة فردية، مشاركة، والتحديد المتعدد مع شريط الإجراءات الجماعية.
5. **الفحص والتحقق الكامل**:
   - تجميع التطبيق والتحقق من عدم وجود أي خطأ برمجي.
